# Working on the Fujin repo

Fujin is a shadcn-compatible component registry. Read `docs/plan.md` before
making structural changes; it records the decisions and why they were made.

## Layout

- `apps/www/registry/fujin/**` is the **only** place shipped component code
  lives. Imports inside it use `@/registry/fujin/<tier>/<file>`; the shadcn CLI
  rewrites them on install.
- Items are declared in `apps/www/registry/fujin/<tier>/_registry.ts` and
  composed in `apps/www/registry/registry.ts`.
- `apps/www/public/r/` and `apps/www/registry/__index__.ts` are generated.
  Never edit them by hand.
- `templates/*/components/ui` are generated by `pnpm templates:sync`. Change
  the registry source, not the template copy.

## Component rules

- Base UI primitives from `@base-ui/react/<part>`. Use `render`, not `asChild`.
- Plain function components with `React.ComponentProps`/primitive `Props` types;
  no `forwardRef`.
- `data-slot="<name>"` on every rendered part; style with theme tokens only.
- `"use client"` only when the file uses state, effects, events or Base UI.
- Composites: behaviour in `lib/<name>/` (no classNames), markup in
  `components/` (no business logic).
- Accessibility bar is WCAG 2.2 AA: 24px minimum targets, solid focus rings,
  no drag-only interactions, keep entered values, never block paste.
- Cross-item dependencies use `@fujin/<name>` in `registryDependencies`.
- Every public item needs a complete `meta.fujin` (see
  `packages/schema/src/mcp.ts`). `whenNotToUse` and `pitfalls` matter most.

## Verify before finishing

```bash
pnpm --filter www registry:build
pnpm typecheck
pnpm --filter www build
```

For registry changes that affect templates: run `pnpm --filter www dev`,
then `pnpm templates:sync`, then build both templates.

## Versions

TypeScript is pinned to 6.0.3 on purpose (TS 7 has no tooling API until 7.1).
Next.js 16 ships its docs in `node_modules/next/dist/docs/`; read them
before writing framework code.
